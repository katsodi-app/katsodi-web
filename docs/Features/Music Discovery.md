# Музыкальные чарты и переход в комнату

> Русский · [[docs/en/Features/Music Discovery|English]]

## Зачем нужна
Обновление интерфейса: [[docs/Features/Music Player]] заменяет прежние пять публичных записей SoundCloud исследованной подборкой из 100 треков, а недоступный TikTok — 60 трендовыми треками. Ниже сохранены сведения о возможностях старых источников; они не описывают текущие вкладки SoundCloud/Trending. Новые подборки входят в weekly payload `spotify-all-time`; активация расписания ещё требуется.

Актуальные музыкальные подборки по источникам, список наиболее прослушиваемых треков и быстрый переход к песне в комнате.
## Пользователи и роли
Чарты публичны. «Слушать в комнате» доступно подтверждённому участнику: сервер проверяет активное членство; для новой комнаты создаёт приватную музыкальную комнату.
## Пользовательские сценарии
Выбрать Spotify, YouTube, SoundCloud или TikTok; отфильтровать список; открыть источник; нажать «Слушать в комнате». Трек открывается в текущей доступной музыкальной комнате либо в новой приватной. Видеокомната при этом не меняется.
## Правила поведения
- Spotify и YouTube: по 150 глобальных записей из опубликованных недельных рейтингов Kworb, с ссылкой на методику источника и периодом. У видео сохраняется опубликованное название без догадок об исполнителе.
- «Больше всего прослушиваний» — существующий глобальный Spotify all-time, а не локальная статистика Katsodi.
- SoundCloud: официальный американский Top 50; публичный HTML раскрывает метаданные только пяти записей. Настроенный официальный API позволяет получить доступные треки плейлиста. 150 записей из этого источника не выдумываются, регион и фактическое число видны.
- TikTok проверен в публичном браузере: список песен не доступен. Показываются состояние недоступности и ссылка на официальный источник, без обхода защиты.
- Ошибка обновления сохраняет последнюю успешную подборку и её дату; неполный разбор Spotify/YouTube не заменяет полный снимок. Снимок старше восьми дней помечается устаревшим.
## Интерфейс и состояния
Вкладки источников, поиск, регион, дата/период, счётчик доступных позиций и кнопки комнаты в строках и на странице песни. Внешние плееры сохраняют существующее согласие и ограничения автозапуска.
## Техническая реализация
`music-discovery.ts` задаёт схемы и безопасные URL; `music-chart-sources.ts` читает публичный HTML. `music-actions.ts` проверяет сеанс и меняет источник либо создаёт комнату. `musicLibraryData` читает публичные снимки из Supabase с bundled fallback; новые all-time slugs доступны без пересборки.

`npm run music:refresh` создаёт локальный снимок; `--database --no-write` публикует его в Supabase. `node scripts/build-music-chart.mjs` обновляет all-time только после проверки всех 150 треков; затем `npm run music:refresh -- --database --no-write --all-time-only` публикует его. Weekly workflow выполняет обе операции по понедельникам в 06:00 UTC, только после размещения workflow в GitHub и настройки secrets. Сам код в этой сессии не отправлялся в remote.
## Данные и доступы
Миграция `20261108002300_music_discovery.sql`: публичные `music_chart_snapshots`, запись только service role. В workflow нужны `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`; SoundCloud API дополнительно использует `SOUNDCLOUD_CLIENT_ID` / `SOUNDCLOUD_CLIENT_SECRET`. Пользовательские данные не входят в снимки.
## Безопасность и приватность
Нет записи медиа и обхода защиты. Ключи остаются на сервере. URL треков, изображений и источников валидируются; анонимные пользователи не меняют чарты или комнаты. Приватные плейлисты не импортируются.
## Критерии приёмки
Unit: разбор и схемы, сохранение старого снимка при отказе источника, безопасность URL, официальный SoundCloud OAuth, права таблицы и переход в комнату. E2E: вкладки, поиск, фактические количества, состояния SoundCloud/TikTok, обе локали и кнопки комнаты.
## Ограничения и следующие шаги
Применить миграцию 23; разместить workflow и настроить его secrets. У новых музыкальных комнат остаётся зависимость от миграции 22. Реальный API импорт требует учётных данных провайдера. Живой переход между двумя аккаунтами принимается отдельно в [[docs/Acceptance Checklist]].

# Настольное приложение

> Русский · [[docs/en/Features/Desktop Application|English]]

> Заменяется собственным приложением: [[docs/Features/Native Desktop Client]]. Эта заметка описывает прежнюю оболочку «сайт в окне».

## Зачем нужна
Настольный клиент Katsodi для Windows: небольшая закрытая оболочка на Electron, которая открывает настоящий сайт Katsodi в отдельном окне. Это не второй интерфейс. Страницы, дизайн, языки, темы, аккаунты и комнаты — те же, что на сайте, и меняются вместе с ним. Более лёгкий способ установки — [[docs/Features/Installable Web App]]; общая настройка нагрузки — [[docs/Features/Low Resource Mode]]. Исходное задание — внутреннее описание приложения.

## Пользователи и роли
Все, кто может пользоваться сайтом. Оболочка не даёт дополнительных прав: гость, подтверждённый пользователь, участник, модератор, владелец и администратор определяются сервером так же, как в браузере ([[docs/Features/Server Authorization]]). В клиенте нет режима администратора, тестового аккаунта или переключателя ролей.

## Пользовательские сценарии
- Запустить Katsodi из меню «Пуск»: окно открывает `/home` и помнит размер и положение.
- Войти в аккаунт внутри приложения. У приложения свой профиль: вход на сайте в Chrome или Edge не переносится, и приложение не читает данные других браузеров.
- Подтвердить почту или сбросить пароль по письму: ссылка открывается в системном браузере и завершается там (в ссылке одноразовый хеш токена, который проверяет сервер, поэтому подойдёт любой браузер). После этого войти в приложении.
- Подключиться к голосу: микрофон разрешён только странице самого Katsodi.
- Провести демонстрацию ссылки: окно выбора спрашивает, что показать. «Это окно Katsodi» — для сайта внутри комнаты (страница обрезает поток до области сайта до публикации); другое окно или экран — для режима отдельного окна.
- Открыть ссылку `katsodi://room/<id>`, `katsodi://invite/<token>` или `katsodi://open/<раздел>`; повторный запуск передаёт ссылку уже открытому окну.
- Пропала связь: локальный экран объясняет причину и предлагает «Повторить».

## Правила поведения
- Один экземпляр и одно окно продукта. Закрытие окна в Windows и Linux завершает приложение, звонок и демонстрацию; в трее ничего не остаётся.
- В окне продукта показывается только утверждённый origin. Другие ссылки `https` открываются в системном браузере; всё остальное (`file:`, `javascript:`, другие схемы, обычный `http`) отклоняется. `window.open` не создаёт окон приложения.
- Загрузки принимаются только для файлов самого приложения, через системный диалог сохранения. Загруженное не открывается и не запускается.
- Показ экрана не начинается без выбора в окне выбора; нет источника по умолчанию и запомненного источника, системный звук не подключается (иначе в эфир попал бы звонок комнаты).
- После пробуждения компьютера страница заново читает личность и состояние комнаты, прежде чем доверять старым данным.
- Локальные черновики остаются локальными. Оболочка не делает данные браузера многопользовательскими и не синхронизирует профиль браузера с профилем приложения.

## Интерфейс и состояния
Область содержимого — сайт без изменений. Нативные части: обычная системная рамка окна; меню (Файл, Правка, Вид, Переход, Справка) на языке страницы со стандартными сочетаниями, масштабом, полным экраном, «Назад/Вперёд», настройками, «О приложении», пунктом «Аппаратное ускорение» (для диагностики, нужен перезапуск) и «Скопировать сведения для диагностики»; окно выбора источника; экран восстановления с пятью причинами: нет сети, сервер недоступен, сертификат не проверен, ошибка загрузки, страница аварийно закрылась. Локальные экраны повторяют язык и палитру страницы и используют тот же шрифт Manrope. Минимальный размер окна — 320×420, поэтому телефонная вёрстка остаётся доступной.

## Техническая реализация
- `desktop/` — отдельный пакет (Electron 45.3.1, Electron Forge 8.0.1, `@electron/fuses` 2.1.3; свой `package-lock.json`). Пакеты сайта не изменены. Исходники собирает корневой `esbuild` (`desktop/scripts/build.mjs`) в `desktop/dist`: `main.js`, два preload-скрипта в песочнице и `local/` (две страницы). Сервер Next.js, база данных и секреты не упаковываются, локального сетевого сервиса нет.
- Origin: production-сборка загружает только `https://katsodi.watch`; константа вшита при сборке, и ни файл, ни аргумент, ни переменная её не меняют. Сборка для разработки принимает только loopback-origin из `KATSODI_DESKTOP_DEV_ORIGIN` и использует отдельный профиль («Katsodi Dev»).
- Рендерер: `contextIsolation`, `sandbox`, без Node (включая воркеры и вложенные фреймы), `webSecurity` включён, `<webview>` запрещён, фоновое замедление включено, DevTools в production отключены. Раздел сессии `persist:katsodi`; cookie остаются HttpOnly, главный процесс их не читает.
- Мост (`src/lib/platform/bridge-contract.ts`, протокол 1): у `window.katsodiDesktop` ровно две функции — `getCapabilities()` и `onNativeEvent(listener)` (событие `resume`). Preload также сообщает язык и палитру страницы (два значения из фиксированных списков). Каждый обработчик IPC проверяет настоящий фрейм-отправитель, его окно и документ; каналы фиксированы. Сайт работает без моста и считает неизвестный протокол отсутствием моста (`src/lib/platform/desktop.ts`).
- Строки берутся из раздела `desktop` файла `src/lib/i18n.ts`, палитры — из `src/app/signal.css`, оба при сборке: второго источника переводов и цветов нет.
- Fuses в упакованной сборке: RunAsNode выключен, `NODE_OPTIONS` и `--inspect` не действуют, шифрование cookie включено, проверка целостности ASAR включена, загрузка только из ASAR, без дополнительных прав `file:`.

Команды (из корня репозитория):

| Команда | Что делает |
| --- | --- |
| `npm run desktop:install` | Ставит инструменты и скачивает среду Electron |
| `npm run desktop:dev` | Собирает оболочку для разработки и открывает её на уже запущенном сервере (сам сервер не запускает) |
| `npm run desktop:build` | Production-сборка в `desktop/dist` |
| `npm run desktop:typecheck` | Строгая проверка TypeScript |
| `npm run desktop:test` | Модульные тесты политик (31 тест) |
| `npm run desktop:test:integration` | Настоящий Electron на локальном тестовом сервере (9 проверок) |
| `npm run desktop:package` | Распакованное приложение в `desktop/out/Katsodi-win32-x64` |
| `npm run desktop:make` | Установщик Squirrel в `desktop/out/make` |
| `npm run desktop:verify` | Список файлов пакета, поиск секретов, production-origin и fuses |
| `npm run desktop:perf` | Замеры памяти и процессора по дереву процессов, JSON |

Машина сборки: Node.js 22.13 или новее (требование Forge 8; проверено на 26.13.0) и npm. Пользователю нужно только само приложение. PowerShell: `$env:KATSODI_DESKTOP_DEV_ORIGIN = "http://localhost:3000"; npm run desktop:dev`.

## Данные и доступы
- Профиль: `%APPDATA%\Katsodi` (для разработки — `%APPDATA%\Katsodi Dev`). В нём сессия Chromium (cookie, local storage, HTTP-кэш) и `desktop-settings.json`.
- `desktop-settings.json` (версия 1) содержит только границы окна, последние язык и палитру страницы и переключатель аппаратного ускорения. Файл проверяется при чтении, записывается атомарно и с задержкой. В нём нет токенов, cookie, чата, снимков экрана и данных аккаунта.
- Удаление через «Установленные приложения» Windows убирает программу; чтобы удалить и локальный профиль, удалите `%APPDATA%\Katsodi`.

## Безопасность и приватность
Таблица разрешений (`desktop/src/main/permissions.ts`), по умолчанию — отказ:

| Разрешение | Решение |
| --- | --- |
| Микрофон | Только верхний фрейм самого Katsodi |
| Камера | Отказ: Katsodi не публикует веб-камеру |
| Захват экрана | Верхний фрейм Katsodi; источник — только через окно выбора |
| Выбор динамиков, запись в буфер обмена | Верхний фрейм Katsodi |
| Полный экран | Любой фрейм (нужен плеерам провайдеров) |
| Геолокация, уведомления, чтение буфера, MIDI, USB, serial, HID, Bluetooth, DRM, файловая система, захват указателя и всё остальное | Отказ |

Встроенные фреймы провайдеров не доверенные: у них нет preload, моста и доступа к устройствам. Проверка TLS не ослабляется; при ошибке сертификата показывается экран восстановления. Заголовки и миниатюры окон из окна выбора остаются на устройстве и не журналируются. Deep link разбирается в фиксированное действие и ограниченный идентификатор; токены не журналируются, сервер проверяет доступ заново. «Скопировать сведения для диагностики» — явное действие, в нём только версии и размеры процессов. Общие правила: [[docs/Security and Privacy]].

## Критерии приёмки
Проверено на Windows 11 (сборка 26200) x64 с Electron 45.3.1, 2026-11-12:

- `npm run desktop:test`: 31 модульный тест проходит (origin, навигация, deep links, разрешения, настройки, границы окна, запросы захвата, данные моста).
- `npm run desktop:test:integration`: 9 проверок проходят в настоящем Electron на локальном тестовом origin: защищённые настройки окна и постоянная сессия; у моста две функции, у страницы нет `require`/`process`; чужой фрейм не получает мост, микрофон и камеру; верхний фрейм получает микрофон и никогда — камеру, геолокацию и уведомления; чужие ссылки уходят в (подменённый) системный браузер, второе окно не появляется; окно выбора корректно отменяется, а захват собственного окна обрезается через `CropTarget`/`cropTo` (Region Capture в этом Electron работает); повторный запуск передаёт deep link и завершается; экран восстановления появляется на языке и в палитре страницы и «Повторить» возвращает на страницу; сохраняются только нативные настройки.
- `npm run desktop:package` и `npm run desktop:verify` проходят: 13 разрешённых файлов в архиве, production-origin, нет похожих на секреты строк и source maps, все семь fuses настроены.
- Упакованный `katsodi.exe` запустился, загрузил `https://katsodi.watch/home` (страница сообщила оболочке язык и палитру) и не оставил процессов после выхода.

Реестр соответствия. Оболочка показывает маршруты самого сайта, поэтому интерфейс совпадает по построению; «проверено» ниже означает проверку именно в оболочке.

| Раздел | Состояние в настольной оболочке |
| --- | --- |
| Лендинг, главная, обзор, юридические страницы и источники | Те же страницы. `/home` загружена с production в упакованном приложении; остальные в оболочке ещё не открывались |
| Локальные комнаты, сохранённое, фандомы, музыка, поиск, настройки | Те же страницы; в оболочке ещё не проверены |
| Вход, регистрация, подтверждение почты, сброс пароля | Тот же серверный процесс и cookie; вживую в оболочке не проверено |
| Общие комнаты, чат, очередь, модерация, друзья, администрирование | Те же серверные контракты; вживую в оболочке не проверено |
| Голос | Путь разрешения микрофона проверен на поддельном устройстве; настоящий звонок LiveKit в оболочке не проверен |
| Демонстрация ссылки внутри комнаты | Окно выбора и обрезка проверены на тестовой странице; публикация в LiveKit в оболочке не проверена |
| Демонстрация в отдельном окне | Сайт открывается в системном браузере, его окно предлагается в окне выбора; в настольном приложении без звука (отличие от Chrome) |
| Плееры провайдеров (YouTube, VK, Vimeo, SoundCloud, Spotify) | Те же встраивания; воспроизведение в оболочке не проверено. В Electron по умолчанию нет Widevine, поэтому защищённое DRM воспроизведение, вероятно, недоступно |
| Hyperbeam | В проекте не настроен; состояние «недоступно» без изменений |
| Полный экран | Разрешение выдаётся; поведение в оболочке не проверено |
| Deep links | Проверены повторным запуском в сборке для разработки; регистрация протокола установщиком не проверена |

Измеренное потребление (упакованное приложение, `/home` с production, окно активно, прогрев 25 с, 41 замер раз в секунду; Intel Core Ultra 5 226V, 8 логических ядер, 16 ГБ ОЗУ; обычный режим):

| Показатель | Результат | Исходная цель |
| --- | --- | --- |
| Частный рабочий набор всего дерева (4 процесса), медиана / пик | 208,6 / 216,8 МиБ | ≤ 250 МиБ: выполнено |
| Сумма рабочих наборов (общие страницы считаются повторно), медиана | 469,1 МиБ | для справки |
| Процессор, 100% = одно логическое ядро, среднее | 6,22% | < 1%: не выполнено |
| Размер распакованного приложения | 357 МиБ | для справки |
| Процессов после выхода | 0 | 0 |

Показатель процессора в простое цель не выполняет. Причина в этом проходе не профилировалась (на production-сайте ещё не было режима экономии, а на `/home` есть движущиеся элементы); это открытая задача, а не принятое исключение.

## Ограничения и следующие шаги
- Только Windows x64. Сборки для macOS и Linux не делались и не проверялись; о них ничего не утверждается.
- Установщик и исполняемые файлы — неподписанные локальные сборки: Windows SmartScreen покажет предупреждение. Для подписи нужен сертификат владельца (`certificateFile`/`certificatePassword` или `signWithParams` в настройках Squirrel, из секретов вне репозитория). Установщик собран, но здесь не запускался.
- Автообновления нет: нет канала обновлений. Обновление — установка новой сборки. Канал, его подпись и публикация — решения владельца, они не настраивались.
- Нет режима трея, автозапуска и нативных уведомлений (текущим функциям они не нужны; возможность сообщает `nativeNotifications: false`).
- Слабые и старые физические компьютеры не проверялись. Electron 45 требует 64-битный процессор и версию Windows, которую ещё поддерживает Chromium; 32-битный или примерно 25-летний компьютер это приложение запустить не сможет, и урезанная версия на устаревшем движке не предлагается. Там, где работает поддерживаемый браузер, подойдут сайт или устанавливаемое веб-приложение.
- Не измерено: время запуска, простой в фоне, комнаты, голос, демонстрация, длительные прогоны и утечки; сравнение с PWA; режим экономии в оболочке.
- Живая приёмка в оболочке (два аккаунта, голос, демонстрация, провайдеры) впереди, как и для сайта: [[docs/Acceptance Checklist]].

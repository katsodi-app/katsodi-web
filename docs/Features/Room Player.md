# Проигрыватель комнаты

> Русский · [[docs/en/Features/Room Player|English]]

## Зачем нужна
Показать видео внутри комнаты по ссылке, а поддерживаемый публичный iframe найти на странице источника. Один источник хранится в общей комнате и передаётся её участникам.

## Пользователи и роли
Участники видят плеер. Владелец и активные модераторы меняют или удаляют источник; обычный участник, гость, удалённый участник и неподтверждённый аккаунт менять источник не могут. Закрытая комната не разрешает изменения и поиск плеера.

## Пользовательские сценарии
Указать ссылку при создании либо вставить её в поле «Что будем смотреть?» и нажать «Показать всем». Источник сохраняется через RPC, после обновления комнаты у участников заменяется плеер. Получение snapshot использует существующий polling раз в три секунды. Поддерживаемое видео можно запустить, развернуть и открыть отдельно.

## Правила поведения
- YouTube: watch, youtu.be, shorts, live и embed с корректным 11-символьным ID преобразуются в официальный embed. Неправильный ID не объявляется поддерживаемым.
- Публичная HTTPS-ссылка с путём .mp4 или .webm открывается нативным video. Поддержка кодеков и доступность файла зависят от браузера и сервиса.
- Kinogo.is: сервер читает только страницу конкретного произведения, ищет iframe и принимает только проверенный адрес api.nextembed.ws/embed/movie/ID или /series/ID. Посторонние iframe не выводятся.
- Re:ANIME: публичные метаданные произведения → JSON API → проверенный FlixCloud iframe, с сохранением номера серии. LiveBall: конкретный матч → проверенный iframe либо оригинальная страница с native-плеером. Подробности — [[docs/Features/Player Discovery]]. Остальные публичные страницы проходят общий HTML-поиск — [[docs/Features/Generic Player Discovery]]. Вход и ограничения доступа не обходятся.
- **Сейчас играет:** для ссылок YouTube, Vimeo, SoundCloud, Dailymotion и Rutube в шапке плеера показываются название, автор, сервис, обложка и (для Vimeo) длительность из официального oEmbed сервиса (`src/lib/server/media-details.ts`, `/api/rooms/[id]/media`, только активным участникам, кеш 10 минут). Длина полей ограничена, обложка должна быть публичным HTTPS-адресом и загружается без referrer, текст выводится как текст.
- **VK Видео:** VK показывает свои видео на других сайтах только через официальный код встраивания («Ещё» → «Экспортировать») с `hash` для каждого видео. Комната принимает ссылку `video_ext.php` из этого кода или весь вставленный код `<iframe>` и встраивает собственный плеер VK (`vkEmbed` в `src/lib/providers.ts`). Если на сервере задан `VK_ACCESS_TOKEN`, обычная ссылка на видео, трансляцию или клип VK находится автоматически через официальный метод API VK `video.get`, чьё поле `player` и есть эта ссылка встраивания (`src/lib/server/vk-video.ts`, кеш как у остального поиска). Принимается только плеер VK `video_ext.php` с hash, в журнал пишется только числовой код ошибки VK. Без ключа или если VK отказывает (приватное видео, встраивание запрещено, неподходящий тип ключа), комната показывает подсказку про код экспорта. Katsodi не подбирает hash и не читает страницы VK, которые требуют входа. Какие типы ключей VK разрешает для `video.get`, пока не проверено: сначала попробуй сервисный ключ приложения; если в журнале сервера `VK video.get error 28` или `15`, нужен ключ пользователя с правами `video` и `offline` (сервисный ключ заработал 2026-11-05). **VK показывает встроенный плеер только на HTTPS-страницах с доменным именем:** на `http://127.0.0.1` и даже `https://127.0.0.1` плеер пишет «Видео недоступно», на `https://localhost` и настоящих HTTPS-доменах — играет (проверено 2026-11-05). Для локальной проверки VK запусти `npm run dev:https` (самоподписанный сертификат; при первом запуске Next предложит установить локальный центр сертификации), открой `https://localhost:3000`, задай `NEXT_PUBLIC_APP_URL=https://localhost:3000` и добавь `https://localhost:3000/auth/callback**` в redirect URL Supabase.
- **Для YouTube есть общий таймлайн** после миграции 0900: play/pause/seek ведущего доходят до всех участников — [[docs/Features/Shared Playback]]. Правило ниже относится ко всем остальным источникам.
- **Встроенный плеер не означает синхронный просмотр.** Каждый запускает видео у себя. Play/pause/seek, голос и общий таймлайн на этом этапе не синхронизируются; UI и capabilities показывают sync=false.

## Интерфейс и состояния
Фирменный адаптивный кинозал 16:9 с минимальной высотой 200px, нативными контролами провайдера, полноэкранным режимом, ссылкой на источник и повторной проверкой. RU/EN. Состояния: поиск, iframe, native video, неподдерживаемый источник, отсутствие iframe, запрет встраивания, ошибка сети/видео. Cross-origin iframe не позволяет достоверно узнать, началось ли воспроизведение; загрузка iframe не считается доказательством успешного показа фильма.

## Техническая реализация
RoomStage → RoomPlayer; knownPlayer и readPlayerResolution проверяют адреса на клиенте. GET /api/rooms/[roomId]/player сначала проверяет подтверждённый аккаунт, RLS, активное членство и открытую комнату, затем берёт URL из БД. URL из query endpoint не используется. player-resolver запрашивает фиксированные origin проверенных рецептов без redirect, до 8 секунд на запрос и 15 секунд на поиск; HTML до 2 МиБ/512 КиБ, JSON до 256 КиБ. Исходный HTML не вставляется в DOM Katsodi и не исполняется сервером; original-page fallback живёт на origin сервиса в iframe. Кеш метаданных до пяти минут, ошибки до 30 секунд, максимум 128 записей и четыре параллельных поиска; одинаковые запросы объединяются. Видео сервер не проксирует и не скачивает.

## Данные и доступы
Миграция supabase/migrations/20261102000500_room_player.sql добавляет nullable source_updated_at и set_room_source(room,url). Null означает неизвестное время предыдущей смены, а не выдуманное событие. RPC проверяет verified_user, активную роль owner/moderator, закрытие комнаты, блокирует строку комнаты и ограничивает частые изменения двумя секундами. Нужна существующая foundation-схема; миграция независима от chat_media и fandom-связи. Старые комнаты читаются без новой колонки, но форма изменения источника отключена до применения миграции.

## Безопасность и приватность
Общий поиск запрашивает публичные HTTPS-origin с проверкой DNS, закреплением IP и отдельной проверкой redirect — [[docs/Features/Generic Player Discovery]]. Нет исполнения сторонних скриптов на сервере, проксирования видео, передачи cookies/credentials провайдерам, обхода DRM, авторизации, геоблокировки или embed-защиты. Найденный iframe проверяется на X-Frame-Options и ограничивающий frame-ancestors. Браузер продолжает применять политики провайдера. Iframe имеет sandbox scripts/same-origin/presentation без разрешения навигации верхней страницы и popup; fullscreen/encrypted-media/picture-in-picture разрешены для штатного плеера. Реклама внутри сервиса не фильтруется. API-ответ private, no-store; кеш резолвера проверяется только после авторизации запроса. В кеше URL источника и плеера, без room ID, cookies и профилей.

## Критерии приёмки
Unit: разбор URL, поддельные origin, недопустимые iframe, скрипты, CSP, redirect, oversized HTML, кеш, проверка членства API. PostgreSQL/PGlite: owner/moderator/member/outsider, throttle, kick, закрытая комната и общая сохранённая ссылка. Браузерный стенд: iframe, RU/EN, два независимых контекста с разными ролями и получение новой ссылки через polling. Моки не обходят авторизацию рабочих маршрутов. Фактические результаты — [[docs/Verification]].

## Ограничения и следующие шаги
Облачная миграция в этом этапе не применялась; publishable key не даёт DDL-доступа. Перед изменением источника в настоящей общей комнате применить миграцию и принять сценарий двумя подтверждёнными аккаунтами — [[docs/Backend Setup]]. Локальные черновики поддерживают YouTube/прямые файлы, а серверное обнаружение плееров доступно только членам общей комнаты. Собственный HLS/DASH-плеер, загрузка пользовательских видео, разбор закрытых API и универсальное извлечение любых сайтов отсутствуют. Следующий самостоятельный этап — общий таймлайн через поддерживаемый provider API, начиная с YouTube, с серверным источником истины.

## Источники и фактическая проверка
- [YouTube: официальный формат embed](https://developers.google.com/youtube/player_parameters).
- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) — основа будущего управления таймлайном, сейчас команды API не реализованы.
- [MDN: video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video).
- [MDN: frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).
- 2026-11-02: [страница «Дюны»](https://kinogo.is/240-diuna.html) вернула HTTP 200 и публичный iframe [NextEmbed](https://api.nextembed.ws/embed/movie/36036). Новый резолвер реально вернул именно его; embed-страница вернула HTML 200 без XFO/CSP-запрета. Это проверка обнаружения/заголовков, не доказательство воспроизведения видео во всех регионах.
- Дополнительный реальный браузерный стенд показал интерфейс YouTube и NextEmbed, включая кнопку запуска, русскую озвучку и длительность «Дюны». Видео не запускалось; это проверка отображения интерфейса, а не полного воспроизведения.
- [Re:ANIME](https://reanime.to/watch/spirited-away-44grtu): сама страница имеет frame-ancestors 'self', но публичный API предоставляет отдельный FlixCloud iframe. Встраивается проверенный отдельный плеер, ограничения страницы не снимаются. Исследование API и LiveBall — [[docs/Features/Player Discovery]].

# Устанавливаемое веб-приложение

> Русский · [[docs/en/Features/Installable Web App|English]]

## Зачем нужна
Позволяет поддерживаемому браузеру установить Katsodi как приложение (PWA): отдельное окно и значок, тот же сайт и тот же вход, что в этом браузере. Это лёгкий способ «установить» Katsodi, когда на устройстве уже есть поддерживаемый браузер: вторая браузерная среда не нужна. Отдельный клиент для Windows — [[docs/Features/Desktop Application]].

## Пользователи и роли
Все посетители. Установка ничего не меняет в аккаунтах, комнатах и правах.

## Пользовательские сценарии
- Chrome или Edge (компьютер, Android): Настройки → Приложение → «Установить Katsodi» либо пункт установки в самом браузере.
- iPhone и iPad: Safari → «Поделиться» → «На экран „Домой“» (страница это объясняет; iOS не показывает запрос установки).
- Открыть установленное приложение без сети: небольшая страница Katsodi сообщает, что подключения нет, и предлагает «Повторить»; при появлении сети она перезагружается сама.

## Правила поведения
- Кнопка установки появляется, только если браузер действительно предложил установку (`beforeinstallprompt`). Иначе раздел объясняет, где она находится в браузере, или шаги для iOS. Поддельной кнопки нет.
- Общим комнатам, чату, голосу, импорту и изменениям профиля нужна сеть. Ничего не откладывается на потом, совместная работа офлайн не имитируется. Локальные черновики остаются в браузере, как раньше.
- Service worker регистрируется только в production-сборке. В разработке он не регистрируется, а прежняя регистрация удаляется, поэтому горячая перезагрузка не кэшируется.
- Внутри настольного приложения service worker не регистрируется (прежний удаляется): у оболочки свой экран восстановления, поэтому в каждой среде один управляющий кэшем.
- Новая версия service worker не перехватывает открытые страницы: нет `skipWaiting` и `clients.claim`. Она включается после закрытия всех вкладок и окон Katsodi и никогда — во время звонка, демонстрации или незавершённой формы.
- Нет push-уведомлений и фоновой синхронизации: установка не добавляет сервер сообщений.

## Интерфейс и состояния
Настройки → Приложение показывает одно из состояний: кнопка установки с пояснением; «открыт как установленное приложение»; инструкция для iOS; «этот браузер сейчас не предлагает установку»; а в настольном приложении — его версию и пометку, что вход там отдельный. Офлайн-страница использует сохранённые язык и палитру (все пять палитр; System следует устройству), логотип и Manrope.

## Техническая реализация
- `src/app/manifest.ts` → `/manifest.webmanifest`: id `/`, старт `/home`, scope `/`, `standalone`, цвета холста Obsidian, значки 192/512 и maskable 512. `src/app/layout.tsx` добавляет цвет темы, значок Apple и `appleWebApp`.
- Значки получаются из `src/app/icon.svg` командой `npm run icons` (`scripts/generate-app-icons.mjs`) в `public/icons/` (и значки настольного приложения).
- `public/sw.js` (собственный, около 80 строк, без библиотек): заранее кэширует `/offline/index.html`, два набора Manrope и один значок в `katsodi-offline-v1`; отвечает офлайн-страницей на неудавшуюся загрузку страницы; другие запросы не трогает.
- `public/offline/index.html` создаётся командой `npm run offline:build` из строк раздела `desktop` в `src/lib/i18n.ts` и палитр `src/app/signal.css`; модульный тест падает, если сохранённый файл устарел.
- `src/lib/platform/install.ts` (состояние установки, регистрация) и `src/components/platform-runtime.tsx` (подключён в корневом layout).

## Данные и доступы
В Cache Storage лежат четыре публичных файла (страница, два шрифта, значок). Worker не кэширует HTML приложения, ответы API, Server Actions, RSC-данные, скрипты, изображения, приватные медиа, auth-callback, приглашения и снимки комнат: они идут по сети через обычный HTTP-кэш браузера. Старые кэши `katsodi-offline-*` удаляются при активации; другое хранилище не затрагивается.

## Безопасность и приватность
Worker обрабатывает только `GET`-запросы своего origin: загрузки страниц и четыре собственных файла. Он не хранит персональных ответов, поэтому после выхода или потери доступа в его кэше ничего не остаётся. Действующая Content Security Policy уже разрешает worker своего origin (`worker-src 'self'`). Правила согласия на cookie не меняются.

## Критерии приёмки
- Модульные тесты (`tests/unit/platform.test.ts`): список предварительного кэша — ровно четыре публичных файла; нет кэширования на лету, `skipWaiting` и `clients.claim`; загрузка страницы при сбое получает офлайн-страницу; запросы API, RSC, скриптов, изображений, POST и чужих origin не затрагиваются; созданная офлайн-страница актуальна; ключи в обоих языках совпадают.
- Проверено в Chromium на production-сборке (`next start`, 2026-11-12): worker зарегистрирован со scope `/`; в кэше ровно четыре файла; manifest отдаёт ожидаемые имя и три значка; при остановленном сервере `/home` показала офлайн-страницу на русском в палитре Obsidian.
- Не проверено: сам диалог установки браузера (нужен HTTPS или интерактивный браузер), установка на Android, «На экран „Домой“» в iOS, поведение между двумя деплоями, ошибки квоты хранилища и вытеснение браузером.

## Ограничения и следующие шаги
Первое посещение без сети работать не может: офлайн-страница появляется только после одного посещения с сетью. В iOS нет запроса установки и ограничены некоторые веб-API (в частности, захват экрана); это ограничения платформы. Язык и цвета manifest фиксированы (русские метаданные, Obsidian); сами страницы следуют выбору пользователя. Индикатор «обновление готово» не сделан: worker не кэширует ничего устаревающего.

# Общий просмотр

> Русский · [[docs/en/Features/Shared Playback|English]]

## Зачем нужна
Смотреть и слушать вместе на **YouTube, Vimeo и SoundCloud**: когда ведущий запускает, ставит на паузу или перематывает, все в комнате следуют за ним. Остальные источники воспроизводятся независимо — [[docs/Features/Room Player]].

## Пользователи и роли
Управляют просмотром владелец и модераторы комнаты — те же, кто может менять источник. Активные участники следуют. Посторонние, удалённые участники и закрытые комнаты таймлайн не получают.

## Пользовательские сценарии
Ведущий вставляет ссылку YouTube, Vimeo или SoundCloud и нажимает play собственными кнопками сервиса. У участников то же видео или трек перескакивает на тот же момент и запускается. Когда ведущий ставит паузу или двигает таймлайн, участники следуют за пару секунд. Если браузер участника запрещает автозапуск, поверх плеера появляется кнопка «Подключиться к просмотру»; один клик — и он смотрит со всеми.

## Правила поведения
- Источник истины — сервер. Он хранит состояние (`playing`/`paused`), позицию и время обновления и вычисляет текущую позицию по **часам базы данных**, поэтому часы устройств не важны.
- Ведущий публикует события play, pause и окончания воспроизведения, а также перемотку; расхождение больше 1,5 с считается перемоткой.
- Участники пересинхронизируются при каждом новом состоянии и при отставании больше 1,5 с. У участников кнопки YouTube скрыты; локальная пауза исправляется при следующей проверке.
- Программные изменения 1,2 с не считаются действиями пользователя, а ведущий не применяет повторно собственное опубликованное состояние — так не возникает «эха» между несколькими модераторами.
- Смена источника сбрасывает таймлайн: новое видео начинается с остановленного состояния.
- Если браузер отказал в автозапуске, это становится явным действием «подключиться»; автозапуск со звуком не навязывается.

## Интерфейс и состояния
Ведущий: «Ты управляешь просмотром…». Участник: «Воспроизведение идёт синхронно с ведущим», «Ждём, когда ведущий запустит воспроизведение» или подсказка и слой при запрете автозапуска. Ошибка публикации показывается как alert. RU/EN. Без миграции или для несинхронизируемых источников показывается прежний текст о независимом воспроизведении.

## Техническая реализация
Каждый сервис управляется через **официальный API плеера** за единым интерфейсом адаптера (`src/lib/player-adapters.ts`): YouTube IFrame Player API, Vimeo Player SDK, SoundCloud Widget API (миллисекунды). Vimeo и SoundCloud сообщают о перемотке событием; для YouTube перемотка определяется сравнением позиции раз в секунду. Комната синхронизируется, только если хост источника (`syncSource`: youtube.com/youtu.be, vimeo.com, soundcloud.com) и хост найденного плеера (`adapterKind`: youtube.com, player.vimeo.com, w.soundcloud.com) указывают на один сервис. **Dailymotion** не синхронизируется: его текущий API плеера требует скрипт с ID плеера конкретного аккаунта. Файлы: `src/lib/playback.ts`, `src/lib/player-adapters.ts`, `src/lib/youtube-api.ts`, `src/components/synced-player.tsx`; `RoomPlayer` → `SyncedPlayer`. Server Action `updatePlayback`; обновление комнаты содержит `playback` только для синхронизируемых источников. Сигналы Realtime доставляют действия ведущего сразу — [[docs/Features/Room Chat]].

## Данные и доступы
Миграция `20261104000900_room_playback.sql`: таблица `room_playback` (одна строка на комнату: URL источника, состояние, позиция, updated_at, updated_by) с RLS и без прямых прав. `get_room_playback` требует активного членства и возвращает null для другого источника или закрытой комнаты. `set_room_playback` требует подтверждённого активного владельца/модератора, открытую комнату и текущий источник комнаты, принимает позицию от 0 до 48 часов (NaN/Infinity отклоняются) и разрешает одно обновление на комнату раз в 200 мс. В облаке пока не применена — [[docs/Backend Setup]].

## Безопасность и приватность
Личность и роль определяются только сессией в SQL; клиент передаёт комнату, источник, состояние и позицию. Видео не проксируется и не скачивается; его воспроизводит собственный плеер сервиса с его рекламой и ограничениями. Хранится только состояние просмотра — без аудио, видео и истории просмотров, кроме текущей позиции комнаты.

## Критерии приёмки
SQL-тесты PGlite: роли, экстраполяция по часам БД, запрет для посторонних и прямого доступа к таблице, неверные значения и частые запросы, сброс при смене источника, kick и закрытии. Unit-тесты: расчёт таймлайна, распознавание только YouTube, проверка входных данных действия и сопоставление ошибок. Браузерные тесты с заменой API: публикация play/pause/seek ведущего, перемотка и запуск у участников, слой при запрете автозапуска, пауза ведущего доходит до участников, RU/EN, desktop/mobile.

## Ограничения и следующие шаги
С включёнными сигналами Realtime действия ведущего должны доходить примерно за секунду; без них — при следующем обновлении (до ~3 с). Только YouTube, Vimeo и SoundCloud; Dailymotion требует ID плеера, Twitch пока не распознаётся. Нет очереди и переключателя «смотреть отдельно». Реальный звук между двумя аккаунтами не проверялся; браузерные тесты используют замены API YouTube, Vimeo и SoundCloud.

# Обнаружение плееров

> Русский · [[docs/en/Features/Player Discovery|English]]

Обновление 11.11.2026: Re:ANIME, LiveBall и FlixCloud удалены; эти хосты и поддомены не передаются общему парсеру, включая редиректы. Остаётся только рецепт Kinogo и общий поиск других источников. См. [[docs/Features/Publication Content Cleanup]]. Ниже сохранена история прежней реализации, а не текущие capabilities удалённых интеграций.

## Зачем нужна
Находить доступный плеер по ссылке на произведение или матч. Расширяет [[docs/Features/Room Player]] проверяемыми рецептами для разных сайтов.

## Пользователи и роли
Активные участники открытой общей комнаты. Смена источника остаётся доступной владельцу и модератору. Права API и RLS не меняются.

## Пользовательские сценарии
Вставить Re:ANIME /anime/slug или /watch/slug?ep=N: сервер определит IDs именно этого произведения, запросит публичный JSON и проверит отдельный FlixCloud iframe. Ссылка на LiveBall /match/ID: найти проверенный iframe либо показать исходную страницу матча с переходом к #player_block. Если трансляция ещё не опубликована, показать понятное сообщение и ссылку на сайт.

## Правила поведения
- Рецепты имеют версии: kinogo-html-v1, reanime-flix-v1, liveball-match-v1. Остальные сайты проходят отдельный ограниченный поиск с DNS/IP-проверками — [[docs/Features/Generic Player Discovery]].
- Эпизод Re:ANIME сохраняется, диапазон 1–5000; повторные/нечисловые параметры ep отклоняются. Кеш различает серии.
- IDs читаются только из примитивных метаданных запрошенного slug, без исполнения JavaScript. API-адрес строится на фиксированном origin.
- Принимаются только NextEmbed movie/series и FlixCloud /e/ID с проверенными параметрами v=1/2, autoPlay=false. Произвольные URL, токены и redirect не принимаются.
- Отдельный iframe проверяется по собственным CSP/XFO. Запрет встраивания страницы каталога не переносится автоматически на другой публичный iframe.
- Native-плеер LiveBall остаётся на исходной странице. Навигация и реклама сервиса сохраняются, логин/географические ограничения сервиса продолжают действовать.
- Кнопка «Повторить» повторяет запрос; отрицательный кеш может действовать до 30 секунд. Это обнаружение плеера, а не общий таймлайн.

## Интерфейс и состояния
RU/EN: поиск, готовый iframe, «Страница источника», матч ещё не начался, требуется конкретный матч, запрет встраивания, ошибка сети и внешний переход. Страница LiveBall явно подписана как оригинальная страница с навигацией, а не как извлечённый чистый плеер.

## Техническая реализация
src/lib/player-recipes.ts выбирает канонический URL и безопасно читает известную структуру ответа. src/lib/server/player-resolver.ts выполняет HTML → публичный JSON → проверенный iframe или source-page fallback. Общий бюджет 15 секунд, отдельный запрос до 8 секунд; HTML страницы до 2 МиБ, JSON до 256 КиБ, HTML плеера до 512 КиБ. До трёх кандидатов, четыре параллельных поиска, объединение одинаковых запросов, кеш 128 записей (успех 5 минут, ошибка 30 секунд). Новые origin добавляются через отдельный проверенный рецепт и тесты.

## Данные и доступы
Новых таблиц/миграций нет. Источник берётся только из доступной пользователю комнаты. Миграция смены источника остаётся отдельным шагом — [[docs/Backend Setup]]. В кеше публичные метаданные, без room ID, аккаунтов и cookies.

## Безопасность и приватность
Нет произвольного серверного браузера, eval, воспроизведения чужих сессий, передачи cookies или заголовков авторизации, обхода защиты либо проксирования HLS. Исходный HTML не вставляется в DOM Katsodi; original-page iframe исполняется на origin сервиса с sandbox. Специальные рецепты не следуют redirect; общий поиск проверяет каждый переход отдельно — [[docs/Features/Generic Player Discovery]]. Политики браузера и доступность стороннего сайта могут ограничивать просмотр у конкретного участника.

## Критерии приёмки
Unit проверяет серии, поддельные домены, примитивные IDs, URL плеера, отсутствие секретных параметров, CSP отдельного плеера и страницы, scheduled/live fallback. E2E использует настоящие компоненты с изолированными ответами API/iframe, desktop/mobile и обе локали. Результаты — [[docs/Verification]].

## Ограничения и следующие шаги
Это расширяемый механизм, а не гарантия для любого сайта. Изменение публичной структуры может потребовать обновления рецепта. Плеер и источник общие, но play/pause/seek независимы. Возможность загрузить интерфейс не доказывает полноценное воспроизведение во всех регионах.

## Разбор api-anything
Проверен [goodnight000/api-anything](https://github.com/goodnight000/api-anything/tree/e22c3dab9410ca2b24f0dde5731c7834a546581d) на commit e22c3dab9410ca2b24f0dde5731c7834a546581d. Это универсальный инструмент изучения и повторения веб-API, а не готовый извлекатель видеоплееров. Его подход к наблюдению публичных запросов полезен для разработки рецептов. SDK не установлен, чужой setup не запускался и код не копировался. [package.json](https://github.com/goodnight000/api-anything/blob/e22c3dab9410ca2b24f0dde5731c7834a546581d/package.json) требует Node >=22.13, проект работает на Node 20; [лицензия MIT](https://github.com/goodnight000/api-anything/blob/e22c3dab9410ca2b24f0dde5731c7834a546581d/LICENSE). Глобальная установка и публикация сетевых рецептов не нужны для Katsodi.

## Источники и наблюдения
- [Re:ANIME: Spirited Away](https://reanime.to/watch/spirited-away-44grtu?ep=1), [публичный JSON](https://reanime.to/api/flix/199/1?mal=199): обнаружен отдельный FlixCloud iframe. Дополнительно проверены Naruto ep=2 и One Piece ep=1. Проверены метаданные и ответы, не полный просмотр видео.
- [Матч LiveBall, присланный пользователем](https://liveball.sx/match/1493215): обычный браузер показал native-плеер; исходная страница загрузилась в iframe на localhost, #player_block оказался у верхнего края. Headless Chromium получал 403 — это не объявлено универсальной блокировкой сервиса. Видеокнопка вручную не нажималась, cookies не экспортировались.

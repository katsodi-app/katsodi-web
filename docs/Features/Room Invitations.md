# Приглашения в комнаты

> Русский · [[docs/en/Features/Room Invitations|English]]

## Зачем нужна
Безопасно допускать друзей в приватную комнату.

## Пользователи и роли
Только владелец создаёт и отзывает; подтверждённый пользователь принимает.

## Пользовательские сценарии
Владелец получает /join#TOKEN. Получатель открывает ссылку, при необходимости входит и подтверждает присоединение. Список действующих приглашений позволяет отозвать их после перезагрузки.

## Правила поведения
256 случайных бит; SHA-256 в базе; срок 24 часа, UI-лимит 10 новых участников. Redeem блокирует строку приглашения и комнаты, проверяет срок/отзыв/лимит/ban, увеличивает uses только при новом вступлении.

## Интерфейс и состояния
RU/EN, поле для копирования, revoke, generic unavailable. Новый токен показывается только создателю при выдаче и не восстанавливается из БД.

## Техническая реализация
Node crypto randomBytes; create_room_invite/redeem_room_invite/revoke_room_invite. Поле token_hash не разрешено читать через Data API даже владельцу.

## Данные и доступы
Fragment не отправляется в HTTP URL. Для перехода через login токен сохраняется в sessionStorage вкладки; next=/join не содержит credential.

## Безопасность и приватность
Ссылку нельзя публиковать всем. Сервер не возвращает метаданные приватной комнаты до принятия. Компрометацию ссылки устраняет отзыв.

## Критерии приёмки
SQL проверяет исчерпание, срок, отзыв и невозможность обхода удаления. Серверный тест сравнивает hash с возвращённым токеном.

## Ограничения и следующие шаги
PGlite проверяет SQL-логику; конкурентные сетевые запросы в настоящем Supabase и auth-переход с приглашением нужно принять после подключения.

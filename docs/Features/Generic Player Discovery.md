# Поиск плееров на публичных сайтах

> Русский · [[docs/en/Features/Generic Player Discovery|English]]

## Зачем нужна
Пытаться обнаружить плеер на произвольной публичной HTTPS-странице, не требуя заранее добавлять её домен в адаптер. Дополняет специальные рецепты — [[docs/Features/Player Discovery]].

## Пользователи и роли
Активный участник открытой общей комнаты. URL берётся из БД комнаты; перед поиском остаются проверки аккаунта, RLS и членства. Менять ссылку могут только владелец и модератор.

## Пользовательские сценарии
Вставить ссылку на просмотр в общей комнате. Сначала используется готовый адаптер, если он есть; остальные страницы проходят общий HTML-поиск. Найденный публичный iframe проверяется и показывается в кинозале. Если обнаружен native/скриптовый плеер самой страницы, показывается исходная страница с её навигацией. Всегда остаётся внешний переход.

## Правила поведения
- HTTPS, без credentials в URL, IP-литералов, локальных имён и нестандартных портов.
- Разбираются iframe/src/data-src, video, Open Graph video, JSON-LD VideoObject/embedUrl/contentUrl и характерные контейнеры Video.js/JW Player/Plyr/Playerjs. Скрипты не исполняются сервером; JSON-LD читается как ограниченный JSON.
- Iframe с allowfullscreen/autoplay/fullscreen либо структурированными video-метаданными считается объявленным сайтом кандидатом. Успешный HTML 200 и отсутствие запрета embed позволяют показать его оригинальный интерфейс, но не доказывают воспроизведение.
- Необозначенные iframe проверяются на собственный video/плеер и вложенные iframe. Циклы, пустые страницы и страницы входа без признаков плеера не объявляются успешным извлечением.
- Для native video и подписанных потоков показывается исходная страница: HLS/MP4-URL из неё не переносятся в отдельный плеер. Сохраняются UI, реклама и origin сервиса.
- X-Frame-Options и все обнаруженные enforced frame-ancestors учитываются консервативно. Внешний браузер продолжает применять политики сайта.
- **oEmbed — официальный API встраивания сайтов.** Сначала загружается `<link rel="alternate" type="application/json+oembed">` страницы (JSON до 256 КиБ, тот же DNS pinning и проверка redirect). Iframe из ответа типа `video`/`rich` важнее угаданных iframe; поле `html` разбирается как инертное AST и никогда не рендерится. Страница этого плеера всё равно загружается и проверяется на запрет встраивания. Неработающий endpoint — откат к обычным признакам страницы.
- **Известные oEmbed-endpoint'ы** для сервисов, которые не объявляют oEmbed в HTML (точные хосты, проверены вживую 2026-11-04): Dailymotion, Vimeo, SoundCloud и Rutube. Для них iframe из собственного endpoint'а сервиса используется сразу, если он на собственном хосте плеера этого сервиса (например, `player.vimeo.com`), потому что некоторые официальные плееры отвечают отказом не-браузерным запросам. Любой другой хост проверяется как обычно. Список — `src/lib/server/oembed-providers.ts`.
- **Карточки плеера Twitter/X** (`twitter:player`) — объявленные кандидаты на встраивание, как Open Graph video.

## Интерфейс и состояния
Общий поиск доступен и для ранее неизвестного домена; это не обещание готового embed. RU/EN: поиск, встроенный кандидат, оригинальная страница, отсутствие плеера, ограничение доступа/встраивания и сеть. Воспроизведение каждого участника независимо.

## Техническая реализация
knownPlayer → специальные рецепты либо genericPlayer. HTML разбирает parse5 7.3.0 (Node 20), без исполнения JavaScript. Общий поиск: до шести документов, глубина до двух вложений, четыре кандидата на документ, три redirect на загрузку, общий бюджет 20 секунд. HTML до 2 МиБ, заголовки до 32 КиБ; для transport запрашивается identity, неожиданно сжатый ответ отклоняется. На один DNS+HTTPS-запрос до 8 секунд, общий deadline не продлевается редиректами. Кеш/объединение запросов/четыре одновременных поиска наследуются от резолвера комнаты.

## Данные и доступы
Новая схема БД не требуется. API не принимает произвольный URL из query и не превращается в публичный proxy. Нужна существующая серверная комната; смена источника зависит от миграции — [[docs/Backend Setup]]. Локальные черновики не получают серверное обнаружение.

## Безопасность и приватность
DNS проверяется для каждого домена и redirect. Любой частный/служебный адрес в наборе A/AAAA отклоняет запрос. TCP/TLS подключается к проверенному адресу через lookup, hostname/SNI и проверка сертификата сохраняются; повторного DNS-разрешения при подключении нет. BlockList исключает loopback, LAN, link-local, CGNAT, multicast, документационные и переходные диапазоны; IPv6 допускается только из глобального 2000::/3 с исключениями. Cookies, Authorization и Referer не передаются; редиректы не наследуют заголовки авторизации. Нет обхода входа, CAPTCHA, DRM, географических ограничений и embed-защиты. Нет проксирования/загрузки видео, исполнения произвольного сайта на сервере или публикации исследовательских сетевых запросов. Браузерные DNS/сетевые политики при последующей загрузке iframe применяются самим браузером; закрепление серверного IP не управляет DNS устройства участника.

## Критерии приёмки
Проверки публичных/частных IPv4/IPv6, смешанного DNS и pinning, redirect в LAN, циклов redirect, таймаута DNS, размеров/типов ответов, настоящего HTML-парсинга, entity/unquoted/lazy атрибутов, JSON-LD, ограничений CSP и вложенных iframe. Браузерный стенд проверяет неизвестный домен, sandbox и внешний переход на desktop/mobile. Результаты — [[docs/Verification]].

## Ограничения и следующие шаги
«Любой сайт с активным плеером» невозможно гарантировать одним HTML-парсером: JS может загружать плеер через неизвестный API только после взаимодействия, а публичный сайт может запрещать embedding. Сервер не запускает произвольный браузер; для таких сайтов нужны новые проверенные рецепты либо отдельный изолированный worker. HTTP 200 и признаки плеера не подтверждают отсутствие последующего входа или региональных ограничений. Это обнаружение интерфейса, а не синхронный просмотр.

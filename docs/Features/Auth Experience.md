# Понятный вход и регистрация

> Русский · [[docs/en/Features/Auth Experience|English]]

## Зачем нужна
Отдельный спокойный сценарий входа без конкуренции с навигацией по комнатам.

## Пользователи и роли
Гость входит, регистрируется или восстанавливает пароль. Проверка аккаунта остаётся на сервере.

## Пользовательские сценарии
Вкладки «Войти / Создать аккаунт», показ пароля, восстановление и повторное подтверждение. После успешного запроса письма форма заменяется инструкцией «Проверь почту», введённым адресом и понятными следующими действиями.

## Правила поведения
Без конфигурации формы отключены. Состояние письма одинаково для существующих и новых адресов. В ссылках между входом, регистрацией и подтверждением сохраняется безопасный next. Стандартные письма открываются в том же браузере; SMTP не меняется. Ссылку нужно открывать в том же браузере и на том же хосте (`127.0.0.1` и `localhost` считаются разными), потому что PKCE code verifier — cookie, привязанная к хосту. Если его нет, /auth/callback больше не сообщает, что ссылка недействительна: Supabase обычно уже подтвердил почту до перенаправления с code, поэтому ссылка регистрации ведёт на /login с подсказкой «войди с паролем», а ссылка восстановления — на /forgot-password с просьбой запросить новое письмо в этом браузере. Истёкшие и повторно использованные ссылки получают прежнюю общую ошибку. Шаблон подтверждения через token hash (`supabase/templates/confirmation.html` → /auth/confirm) работал бы между устройствами; в облачном проекте он пока не включён — [[docs/Backend Setup]].

## Интерфейс и состояния
RU/EN, тематические цвета, отдельная шапка с логотипом и языком. На desktop слева брендовая композиция, справа форма; на мобильном остаётся форма. Боковое меню, поиск и Companion Dock на auth-страницах отсутствуют. Ошибки доступны через alert, результат через status, показ пароля имеет доступную подпись. Декоративная анимация учитывает reduced motion.

## Техническая реализация
Shell выбирает auth-layout для пяти маршрутов. AuthForm использует существующие Server Actions и useActionState. Новые стили изолированы префиксом auth; профиль и форма комнаты сохраняют свои компоненты.

## Данные и доступы
Email отображается только в текущей форме; данные регистрации не сохраняются в браузерное хранилище. Авторизация, RLS и требования к паролю сохранены.

## Безопасность и приватность
Внешние next не допускаются серверным контрактом. Проверки не создают настоящих аккаунтов и не отправляют письма.

## Критерии приёмки
Браузерные сценарии проверяют переключение форм с next, RU/EN, видимость пароля, отсутствие лишней навигации, recovery/verify и ширину страницы на desktop/mobile. В локальной комнате текст объясняет отсутствие чата и ведёт в общие комнаты.

## Ограничения и следующие шаги
Доставку письма подтвердил пользователь; полный вход по ссылке, профиль и чат двух аккаунтов ещё требуют приёмки. Автоматические UI-тесты не отправляют почту и не проверяют успешный переход реального письма.

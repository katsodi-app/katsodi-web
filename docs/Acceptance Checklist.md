# Чек-лист приёмки

> Русский · [[docs/en/Acceptance Checklist|English]]

Одно место, чтобы проверить Katsodi на ваших настоящих сервисах. Автотесты работают на PGlite, моках и заменах; ничего ниже ещё не проверялось настоящими аккаунтами. Подробности по шагам: [[docs/Backend Setup]], [[docs/Voice Setup]].

## 1. Настроить

- [ ] `.env.local` (не коммитить и не отправлять в чат): `NEXT_PUBLIC_APP_URL=http://127.0.0.1:3000`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- [ ] Голос (по желанию): `VOICE_ENABLED=true`, `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `SUPABASE_SERVICE_ROLE_KEY`, `VOICE_WORKER_SECRET` и планировщик.
- [ ] Общий браузер (по желанию): `HYPERBEAM_API_KEY`.
- [ ] Ссылки VK Видео (по желанию): `VK_ACCESS_TOKEN` (см. [[docs/Features/Room Player]]).
- [ ] Импорт плейлистов (по желанию): `YOUTUBE_API_KEY` (Google Cloud → YouTube Data API v3) и `SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET` (developer.spotify.com → Create app). См. [[docs/Features/Music Rooms]].
- [ ] Supabase Auth: подтверждение почты включено, минимальная длина пароля 12, redirect `http://127.0.0.1:3000/auth/callback**`.
- [ ] Supabase Realtime: включён, публичный доступ к каналам разрешён.
- [ ] Перезапустить dev-сервер и всегда открывать `http://127.0.0.1:3000` (не `localhost`), чтобы ссылки из писем и cookie совпадали.

## 3. Сценарии (A — владелец, B — второй аккаунт, C — третий)

Для каждого аккаунта — обычное и приватное окно, везде `127.0.0.1`.

**Аккаунты**
- [ ] A и B регистрируются, подтверждают почту в том же браузере и входят. Ссылка, открытая в другом браузере, показывает подсказку «войди с паролем».
- [ ] Восстановление пароля работает в браузере, где его запросили.

**Комнаты и чат**
- [ ] A создаёт приватную комнату и приглашение; B входит по ссылке; C комнату не видит.
- [ ] Сообщения, стикеры и картинки появляются в другом окне примерно за секунду (Realtime) или до 3 с (опрос).
- [ ] A назначает B модератором; B выходит и возвращается — снова обычный участник.
- [ ] A удаляет B: у B пропадают чат, плеер, голос и общий браузер.

**Просмотр и очередь**
- [ ] Ссылки YouTube, Vimeo и SoundCloud: A запускает, ставит паузу и перематывает; B следует. Если браузер B запрещает автозапуск, работает «Подключиться к просмотру».
- [ ] B добавляет ссылку в очередь; A нажимает «Включить следующее»; когда видео у A заканчивается, включается следующая ссылка.
- [ ] В шапке плеера видны название, автор и обложка.
- [ ] С `VK_ACCESS_TOKEN`, на `https://localhost:3000` (`npm run dev:https`) или настоящем HTTPS-домене: обычная ссылка `vkvideo.ru/video-…` играет внутри комнаты; без ключа появляется подсказка про код экспорта. На `http://127.0.0.1` сам VK пишет «Видео недоступно».

**Сайт комнаты**
- [ ] A открывает вкладку «Сайт» и показывает встраиваемый сайт (например, статью Википедии); B его видит и листает сам.
- [ ] Сайт, который запрещает встраивание (например, google.com), показывает отказ и «Открыть в новой вкладке»; с Hyperbeam «Открыть в общем браузере» подставляет его адрес.
- [ ] У B (участник) нет поля сайта и кнопки «Закрыть сайт»; «Закрыть сайт» у A убирает его и у B.

**Администратор и запросы фандомов**
- [ ] A (аккаунт, добавленный владельцем в `public.admins`) видит **Панель администратора** на странице аккаунта; `/admin` открывается с разделами Аккаунты, Фандомы, Запросы, Музыка. B на `/admin` получает 404.
- [ ] B предлагает фандом на `/fandoms/request`; A видит его в ожидании и одобряет с комментарием; фандом появляется в каталоге, на него можно подписаться; B видит «Одобрен».
- [ ] B предлагает ещё один; A отклоняет с комментарием; B видит комментарий.

**Музыкальные комнаты (миграция 22)**
- [ ] A создаёт общую комнату «Музыка», B входит. B вставляет плейлист Spotify или YouTube в «Ссылка на плейлист или трек» → «Импорт»: треки в очереди по порядку, видно «Добавлено …».
- [ ] B (обычный участник) нажимает «Включить следующее» и ставит паузу — у A играет то же.
- [ ] A нажимает «Смешать плейлисты»: треки A и B чередуются. У B этой кнопки нет.
- [ ] В видеокомнате вставь ссылку на трек Spotify в очередь: появляется предложение создать музыкальную комнату; «Создать» открывает форму с выбранной «Музыкой», после создания плейлист уже в очереди.
- [ ] Музыкальная комната не помечается неактивной через 10 минут и не удаляется через 30.

**Жизненный цикл комнат (с `npm run voice:worker`)**
- [ ] Создай тестовую комнату и не открывай её 10 минут: в каталоге общих комнат «Неактивна · удалится через … мин». Открытие снимает отметку.
- [ ] Не открывай тестовую комнату 30 минут: её нет ни в каталоге, ни по адресу; картинки её чата удалены из Storage.

**Голос (с LiveKit)**
- [ ] A и B заходят в голос и слышат друг друга; работают выключение микрофона и звука, громкость участника и выбор динамиков.
- [ ] Отключение и включение Wi-Fi переподключает автоматически с выключенным микрофоном; после удаления из комнаты переподключения нет.

**Демо по ссылке (с LiveKit и npm run voice:worker)**
- [ ] B (участник) вставляет ссылку на Википедию в чат и нажимает «Запустить демо»: ссылка появляется в чате; A (владелец) на любой вкладке видит «B хочет показать демо».
- [ ] A принимает. В Chrome/Edge у B во вкладке «Демо» открыт сайт; B нажимает «Начать показ» и выбирает «Эта вкладка». A видит только сайт, без чата B.
- [ ] A рисует и подсказывает клик: пометки видны у B поверх живого сайта и исчезают.
- [ ] A ставит паузу: у B «Пауза — A», картинка у A останавливается; продолжить может только A.
- [ ] Ссылка на сайт, запрещающий встраивание (например, google.com), предлагает B «Открыть сайт и показать».
- [ ] Пометки: A рисует стрелку, рамку, штамп ✓ и текст; B видит их с именем и цветом A, и они не исчезают. B заходит позже (обновить страницу): пометки на месте. A нажимает «Пометки для всех»: теперь рисует и B, A видит имя B. Ластик B не стирает пометки A; «Стереть все» у A убирает всё.
- [ ] A нажимает «Завершить демо»: демо заканчивается у обоих.

**Общий браузер (с Hyperbeam)**
- [ ] A открывает сайт для всех и управляет им; B только смотрит и видит адрес.
- [ ] Удаление B завершает сеанс для всех за несколько секунд.

**Профили, друзья, опыт**
- [ ] A загружает аватар и обложку (с кадрированием, без метаданных о месте); B их видит; C — нет.
- [ ] A добавляет B по @username, B принимает, оба видят профили друг друга; A блокирует C, и C больше не может отправить заявку.
- [ ] Ежедневный визит A начисляется один раз; вход B в комнату A открывает «Первые шаги»; 15 минут в комнате дают опыт за участие.

## 4. Доступность (вручную)

Автоматические проверки axe проходят на всех страницах в обеих темах и размерах; но они оценивают не всё.
- [ ] Только клавиатура: доступны все элементы, виден фокус, окна открываются и закрываются (Escape), вкладки комнаты переключаются стрелками.
- [ ] Экранный диктор (NVDA, VoiceOver или TalkBack) озвучивает заголовки страниц, вкладки комнаты, полосу уровня и управление голосом.
- [ ] Масштаб 200 %: ничего не теряется; при «уменьшении движения» анимации выключены.
